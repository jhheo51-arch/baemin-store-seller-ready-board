# 데이터 항목 설명

| 파일 | 한 행의 의미 | 주요 식별자 | 용도 |
|---|---|---|---|
| sellers.csv | 셀러 1곳 | seller_id | 분야, 상품 수, 신청일, 디지털 숙련도 |
| stage_history.csv | 셀러의 단계 진행 1회 | seller_id + stage_order | 단계 대기, 작업, 재작업, 미완료 분석 |
| inquiries.csv | 문의 1건 | inquiry_id | 문의 유형, 응답, 해결 시간, 72시간 내 재문의 |
| work_tasks.csv | 지원 업무 1건 | task_id | 같은 업무 유입에서 우선순위 정책 비교 |

## 지표 정의

- 준비 완료 소요 시간: 신청 시각부터 판매 준비 완료 시각까지의 달력 일수
- 14일 내 완료율: 신청 후 14일을 관찰할 수 있는 셀러 중 14일 안에 완료한 비율
- 재작업률: 해당 단계를 완료한 사례 중 한 번 이상 보완 작업이 발생한 비율
- 72시간 내 재문의율: 같은 셀러, 같은 문제로 72시간 안에 다시 문의한 건의 비율
- 7일 내 재문의율: 운영 시험에서 같은 셀러, 같은 문제의 재발을 더 넓게 확인하는 비율. Excel KPI에서 사용
- 3일 이내 처리율: 업무 생성 뒤 3일 안에 완료된 업무 비율

`repeat_within_72h`는 가상 원본 데이터에 포함된 단기 재문의 항목이고, 7일 내 재문의율은 실제 시험에서 추가로 계산할 운영 지표입니다. 모든 값은 가상 자료에만 적용되는 정의입니다.

## 정책 모의실험의 별도 계산 기준

`analysis/policy_model.py`는 공개 업무 CSV를 입력으로 56일 동안 하루 80시간을 적용합니다. 완료·미완료 합계는 입력 업무 수와 같아야 합니다. 원본 생성 코드와 정책 결과의 재현은 자동 검사에 포함됩니다.

- `completion_rate`: 전체 업무 중 완료 업무 비율입니다.
- `sla_3day_rate`: **완료 업무 중** 대기일이 3일 이하인 비율입니다. 위 운영 목표 지표의 분모와 다르므로 같은 지표로 비교하지 않습니다.
- `ready_stage_sla_3day_rate`: `progress_stage >= 4`, 즉 상품 등록과 판매 준비 완료 단계에서 **완료된 업무** 중 3일 이하의 비율입니다. 필드명은 기존 결과와 호환되도록 유지했습니다.
- `median_wait_days`, `p90_wait_days`: 완료한 업무의 대기일 중앙값과 90백분위입니다.
- `max_wait_unresolved_days`: 관찰 종료일에 아직 처리하지 못한 업무의 최대 대기일입니다.

재문의 수는 가상 셀러의 전체 문의 건수에서 만든 고정 입력입니다. 실제로 각 날짜까지 접수한 문의만 사용한 모형이 아니므로 미래 정보를 배제한 정책 효과 검증으로 해석하지 않습니다. 업무는 하루의 남은 여력 안에서 전부 처리할 수 있을 때만 완료하며, 처리 여력 이월과 부분 완료는 없습니다. 정책 정렬 점수와 이 한계는 계산 노트북에도 함께 표시합니다.
