# 셀러 레디 보드 PRD

배민스토어 운영지원 채용공고와 공식 셀러 가이드를 읽고, 신규 셀러의 판매 준비 상태를 한눈에 확인하기 위해 만든 운영 도구의 기획서입니다. 공개 자료와 가상 사례를 사용했으며 배민의 현재 내부 도구나 실제 운영 성과를 설명하는 문서는 아닙니다.

## 한 줄 설명

접수 순서만 보는 업무 목록을 정보 정확성, 대기와 재문의, 판매 준비 일정, 담당자 배정 상태로 나누고, 다음 행동과 완료 기준까지 기록하는 셀러 온보딩 운영표입니다.

## 문제를 고른 이유

처음에는 셀러 요청을 빨리 처리하는 것이 가장 중요하다고 생각했습니다. 공식 자료를 확인하면서 상품이 등록되어 있어도 실제 재고가 다르거나 주문 접수 알림을 확인하지 못하면 주문 취소와 고객 이탈로 이어질 수 있다는 점을 알게 됐습니다.

공식 노하우에는 2024년 3~4월 주문 취소 사유로 재고 소진 29.6%, 주문 접수 미인지 19.2%가 소개되어 있습니다. 따라서 온보딩의 완료를 단순한 등록 완료가 아니라, 실제 주문을 받을 수 있는 상태로 정의했습니다.

## 사용하는 사람

- 주 사용자: 신규 셀러의 입점과 판매 준비를 지원하는 운영 담당자
- 함께 보는 사람: 계약, 상품 운영, 정산, 마케팅, 주문 지원 등 확인이 필요한 유관 부서
- 지원 대상: 배민스토어 입점 후 상품과 운영 정보를 준비하는 셀러

## 목표

1. 지금 먼저 확인해야 할 셀러를 빠르게 찾습니다.
2. 셀러별 다음 행동과 다음 확인 시점을 남겨 업무 누락을 줄입니다.
3. 답변을 보낸 시점이 아니라, 필요한 조치가 끝난 시점을 완료로 봅니다.
4. 반복 문의를 안내문, 체크리스트, 내부 절차 개선으로 연결합니다.
5. 다른 부서에 질문할 내용과 받아야 할 답을 명확하게 남깁니다.

## 이 도구가 하지 않는 일

- 배민의 현재 내부 운영 시스템을 대체하지 않습니다.
- 가상 수치만으로 실제 성과 향상을 주장하지 않습니다.
- 셀러의 상황을 자동으로 최종 판단하거나 담당자의 확인을 생략하지 않습니다.
- 실제 팀의 정책, 처리 여력, 단계별 마감 시간을 임의로 확정하지 않습니다.

## 운영 원칙

- 빠른 처리와 정보 정확성을 함께 봅니다.
- 우선순위의 이유가 담당자에게 보여야 합니다.
- 문의에 답한 것보다 문제가 해결됐는지를 확인합니다.
- 여러 기준을 한 점수로 감추지 않고, 어떤 위험 때문에 먼저 보는지 구분합니다.
- 기록에 드는 시간이 절감되는 업무시간보다 커지지 않도록 항목을 최소화합니다.

## 기본 사용 흐름

1. 대기일, 재문의, 오픈일, 담당자, 정보 오류 여부를 갱신합니다.
2. 계산된 우선 신호를 보고 먼저 확인할 셀러를 고릅니다.
3. 다음 행동, 다음 확인 시점, 완료 기준과 방치 위험을 기록합니다.
4. 다른 부서의 판단이 필요하면 질문과 기대 답변을 정해 인계합니다.
5. 같은 문의가 반복되면 안내문이나 체크리스트에서 바꿀 항목을 정합니다.
6. 처리 속도와 정보 오류가 함께 좋아졌는지 확인합니다.

## 우선 신호

아래 순서로 하나의 우선 신호를 표시합니다. 기준값은 가상 사례를 작동시키기 위한 초기값이며 실제 적용 전 팀 데이터로 조정해야 합니다.

| 순서 | 우선 신호 | 초기 판단 기준 | 먼저 확인하는 이유 |
|---|---|---|---|
| 1 | 정확성 확인 | 정보 오류가 `Y` | 잘못된 상품, 계약, 정산 정보가 고객이나 셀러에게 노출될 수 있음 |
| 2 | 장기 대기 및 재문의 | 대기 5일 이상 또는 재문의 2회 이상 | 같은 문제로 오래 기다리거나 반복해서 문의하고 있음 |
| 3 | 판매 준비 임박 | 오픈까지 0~3일 | 오픈 일정은 가까운데 주문 준비가 끝나지 않음 |
| 4 | 담당자 미배정 | 담당자가 없거나 다음 행동이 비어 있음 | 책임자와 후속 행동이 없어 업무가 빠질 수 있음 |
| 5 | 일반 진행 | 위 조건에 해당하지 않음 | 정해진 일정에 따라 확인 가능 |

## 필요한 기능

| 요구사항 | 필요한 동작 | 확인 방법 |
|---|---|---|
| 셀러 상태 기록 | 현재 단계, 이슈, 대기일, 재문의, 오픈 예정일, 담당자, 오류 여부를 입력 | 가상 셀러 12건이 같은 구조로 기록되어 있음 |
| 우선 신호 계산 | 입력값이 바뀌면 정해진 순서에 따라 우선 신호가 다시 계산 | Excel의 노란색 입력 셀을 바꿔 결과 확인 |
| 행동 기록 | 다음 행동과 다음 확인 시점을 반드시 남김 | 우선 셀러의 두 항목이 비어 있지 않음 |
| 완료 판단 | 업무마다 확인 가능한 완료 기준을 작성 | `안내 완료` 대신 정보 일치, 노출, 접수 확인 등으로 기록 |
| 위험 표시 | 방치했을 때 고객, 셀러, 운영에 생길 위험을 기록 | 우선순위 선택 이유와 연결되는지 확인 |
| 협업 인계 | 담당 부서, 질문, 기대 답변, 마감 시점, 셀러 안내 내용을 정리 | 협업 및 인계 탭에서 한 흐름으로 확인 |
| VOC 개선 | 반복 문의의 원인, 바꿀 안내, 확인 지표를 기록 | VOC 개선 탭에서 전후 확인 계획 점검 |
| 지표 관리 | 속도, 재문의, 정확성, 기록 부담을 함께 확인 | KPI 및 출처 탭에서 정의와 주의점 확인 |

## 대표 사례

오픈을 하루 앞둔 셀러의 실제 재고와 등록 재고가 다르고 주문 접수 알림도 확인되지 않은 상황을 대표 사례로 사용합니다.

- 확인 정보: 실재고와 등록 수량, 품절 상품 노출, 주문 접수 기기와 알림, 테스트 주문 결과
- 판단: 오픈 일정만 맞추기보다 주문 취소 가능성을 먼저 줄임
- 다음 행동: 재고를 맞추고 필요하면 품절 또는 판매 중지로 바꾼 뒤 주문 알림을 확인
- 완료 기준: 재고 일치, 판매 중지 상품 비노출, 테스트 주문 알림 확인
- 방치 위험: 오픈 후 주문 취소, 고객 이탈, 셀러 매출 손실

## 확인할 지표

| 지표 | 보는 이유 | 함께 확인할 내용 |
|---|---|---|
| 3일 내 처리율 | 업무 처리 속도 | 정보 오류율 |
| 7일 내 재문의율 | 안내가 실제 해결로 이어졌는지 확인 | 안내 후 완료율 |
| 대기시간 상위 10% 기준 | 평균에 가려진 장기 대기 확인 | 최장 미처리 |
| 정보 오류율 | 빠른 처리 때문에 정확성이 나빠지지 않았는지 확인 | 처리율 |
| 담당자 기록시간 | 도구 자체가 추가 부담이 되는지 확인 | 재문의 절감시간 |

가상 원본 데이터의 `repeat_within_72h`는 짧은 기간 안에 같은 문제가 반복되는지 살펴보기 위한 분석 항목입니다. 운영 시험에서는 문의가 다시 발생하는 흐름을 조금 더 넓게 보기 위해 7일 내 재문의율을 사용합니다.

## 2주 시험

- 1~2일: 팀에서 쓰는 용어와 완료 기준을 맞추고 이전 사례 20건을 입력합니다.
- 3~7일: 매일 10분 동안 먼저 볼 일을 정하고 분류 정확도와 기록 시간을 확인합니다.
- 8~12일: 반복 문의 한 가지의 안내문이나 체크리스트를 바꾸고 재문의와 완료 여부를 확인합니다.
- 13~14일: 운영 담당자와 유관 부서의 의견을 모아 유지, 수정 또는 중단을 결정합니다.

계속 사용하려면 재문의와 장기 대기가 줄고, 정보 오류, 기록 부담, 특정 셀러 방치가 악화되지 않아야 합니다. 2주는 실제 성과를 확정하는 기간이 아니라 더 검증할 가치가 있는지 판단하는 기간입니다.

## 완료 조건

- 입력값을 바꾸면 우선 신호가 다시 계산됩니다.
- 모든 우선 셀러에게 다음 행동과 확인 시점이 있습니다.
- 대표 사례의 문제, 행동, 완료 기준이 PDF와 Excel에서 같습니다.
- 속도 지표와 정확성 지표를 함께 확인할 수 있습니다.
- 다른 부서에 인계할 질문과 기대 답변을 확인할 수 있습니다.
- 가상 자료와 실제 운영 사실이 구분되어 있습니다.
